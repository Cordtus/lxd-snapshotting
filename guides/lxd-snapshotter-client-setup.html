Client guide

Upload node DB snapshots

Connect to the router VPN, install the prefilled config, run one verified seed, then refresh by rsync manually or on a timer.

STAGING_PATH can be local disk or a mounted share. It stays in place; first rsync is full, later rsyncs are incremental.
VPN and SSH handoff

The operator provides a WireGuard config and an SSH private key. The server installs the matching public key with a forced command. Keep both files readable only by root.

2. Install VPN and SSH access

Run as root/sudo on the source node. Use the WireGuard config and upload key provided by the snapshot host operator.

Install transport tools and VPN config
# Run on the source node as root, or prefix with sudo.
apt-get update
apt-get install -y wireguard-tools openssh-client
install -d -m 0700 /etc/wireguard
install -m 0600 "./{WG_INTERFACE}.conf" "/etc/wireguard/{WG_INTERFACE}.conf"
wg-quick up "{WG_INTERFACE}"
wg show "{WG_INTERFACE}"
systemctl enable "wg-quick@{WG_INTERFACE}"
Install upload SSH key
install -d -m 0750 "$(dirname "{SSH_KEY_PATH}")"
install -m 0600 ./upload_key "{SSH_KEY_PATH}"
Test restricted SSH access
ssh -i "{SSH_KEY_PATH}" -o IdentitiesOnly=yes -o BatchMode=yes -p {SSH_PORT} "{UPLOAD_USER}@{BUILDER_HOST}" \
  {REMOTE_COMMAND} status --chain "{CHAIN}"
The router VPN should allow this peer to reach only the upload SSH service.

3. Install helper and config

Run as root/sudo on the source node. Manual runs and timer share this config.

Install tools and helper
# Run on the source node as root, or prefix with sudo.
apt-get update
apt-get install -y python3 rsync tar
install -m 0755 scripts/cosmos-snapshot-upload /usr/local/bin/cosmos-snapshot-upload
Write source-upload.env
install -d -m 0750 "$(dirname "{CONFIG_PATH}")"
umask 077
cat > "{CONFIG_PATH}" <<'EOF'
CHAIN="{CHAIN}"

NODE_HOME="{NODE_HOME}"
DATA_SUBDIR="{DATA_SUBDIR}"
SERVICE_NAME="{SERVICE_NAME}"
SYSTEMCTL_COMMAND="{SYSTEMCTL_COMMAND}"

STAGING_PATH="{STAGING_PATH}"

REQUIRED_DB_DIRS="application.db blockstore.db state.db"
STAGE_DB_DIRS="application.db blockstore.db state.db evidence.db tx_index.db"
DB_MARKER_PATTERNS="CURRENT MANIFEST-* *.sst *.ldb"
LOCAL_RSYNC_EXTRA_ARGS="--numeric-ids"

BUILDER_SSH="{UPLOAD_USER}@{BUILDER_HOST}"
BUILDER_SSH_PORT={SSH_PORT}
SSH_OPTIONS="-i {SSH_KEY_PATH} -o IdentitiesOnly=yes -o BatchMode=yes"
REMOTE_COMMAND="{REMOTE_COMMAND}"
CLIENT_ID=""

RSYNC_DELETE=1
RSYNC_EXTRA_ARGS="--numeric-ids"
VERIFY_REMOTE_RSYNC=1
RSYNC_CHECKSUM=0
BOOTSTRAP_UPLOAD=0
RUN_FINALIZER=1
DRY_RUN=0
UPLOAD_SCHEDULE="{UPLOAD_SCHEDULE}"
EOF
chmod 0600 "{CONFIG_PATH}"
Upload contents

The helper stages only public DB dirs from NODE_HOME/DATA_SUBDIR: application.db, blockstore.db, state.db, evidence.db, and tx_index.db.

It excludes config/, keyrings, validator state, cs.wal, state-sync snapshots/, and arbitrary top-level paths.

Optional local settings UI

Edit exposed client values in a browser. It binds to loopback; use an SSH tunnel if needed.

Serve local config UI
cosmos-snapshot-upload --config "{CONFIG_PATH}" --serve-ui --ui-host 127.0.0.1 --ui-port 8766

4. Preflight paths and VPN access

Run before first dry run. It catches bad paths and checks VPN SSH.

Local path preflight
python3 -c 'from pathlib import Path
node_home = Path("{NODE_HOME}").expanduser().resolve()
data = (node_home / "{DATA_SUBDIR}").resolve()
staging = Path("{STAGING_PATH}").expanduser().resolve()
if not node_home.is_dir():
    raise SystemExit(f"NODE_HOME does not exist or is not a directory: {node_home}")
if not data.is_dir():
    raise SystemExit(f"DATA_SUBDIR does not exist under NODE_HOME: {data}")
if node_home not in data.parents:
    raise SystemExit("DATA_SUBDIR must resolve under NODE_HOME")
if data == staging or data in staging.parents or staging in data.parents:
    raise SystemExit("STAGING_PATH must be separate from source data path")
staging.parent.mkdir(parents=True, exist_ok=True)
staging.parent.chmod(0o750)'
VPN SSH status
ssh -i "{SSH_KEY_PATH}" -o IdentitiesOnly=yes -o BatchMode=yes -p {SSH_PORT} "{UPLOAD_USER}@{BUILDER_HOST}" \
  {REMOTE_COMMAND} status --chain "{CHAIN}"

5. Dry run, seed once, then run routine uploads

Real upload stops the service, stages allowed DB dirs, restarts, transfers, verifies, then requests publish.

Dry runRun first.

Preview local and remote commands.

BootstrapFirst upload only.

Seed empty ingest with a tar stream.

RoutineManual or timer.

Rsync the staging copy.

Dry run
cosmos-snapshot-upload --config "{CONFIG_PATH}" --dry-run
Initial seed
cosmos-snapshot-upload --config "{CONFIG_PATH}" --bootstrap
Normal upload now
cosmos-snapshot-upload --config "{CONFIG_PATH}"
Optional recurring timer

Enable only for automatic refreshes. Change UPLOAD_SCHEDULE before copying.

Install timer
cat > /etc/systemd/system/cosmos-snapshot-upload.service <<'EOF'
[Unit]
Description=Upload Cosmos snapshot database to builder
Wants=network-online.target
After=network-online.target
ConditionPathExists={CONFIG_PATH}

[Service]
Type=oneshot
ExecStart=/usr/local/bin/cosmos-snapshot-upload --config {CONFIG_PATH}
Nice=10
IOSchedulingClass=best-effort
IOSchedulingPriority=7
EOF

cat > /etc/systemd/system/cosmos-snapshot-upload.timer <<'EOF'
[Unit]
Description=Run Cosmos snapshot upload on schedule

[Timer]
OnCalendar={UPLOAD_SCHEDULE}
RandomizedDelaySec=2h
Persistent=true
Unit=cosmos-snapshot-upload.service

[Install]
WantedBy=timers.target
EOF

systemctl daemon-reload
systemctl enable --now cosmos-snapshot-upload.timer
systemctl list-timers cosmos-snapshot-upload.timer
After bootstrap, normal mode rsyncs local and remote staging. The builder validates before publishing.
Adjust or disable the timer later
Timer controls
# Edit OnCalendar in /etc/systemd/system/cosmos-snapshot-upload.timer, then:
systemctl daemon-reload
systemctl restart cosmos-snapshot-upload.timer
systemctl list-timers cosmos-snapshot-upload.timer

# Disable automatic uploads:
systemctl disable --now cosmos-snapshot-upload.timer

6. Common failures

Fix the path, VPN/SSH, or allowlist issue, then rerun. Do not publish partial ingest manually.

  • missing required Tendermint DB directory: wrong node home, data subdir, or DB layout.
  • STAGING_PATH must be separate: choose a path outside the live DB tree.
  • Permission denied or timeout: connect VPN, then check key and account.
  • client is not allowed: identity and chain allowlist do not match.
  • remote rsync verification found pending changes: remote copy differs; retry.
  • systemctl list-timers shows no timer: timer is disabled or not installed.
