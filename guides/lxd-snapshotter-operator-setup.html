2. Create shared storage

Create custom volumes in the existing LXD pool. Builder gets public output read-write; FTP gets read-only.

LXD poolUse existing ZFS-backed LXD storage.

No host bind mount or manual zfs create.

PublicOne volume, two mounts.

Builder read-write; FTP read-only.

IngestBuilder only.

Keep partial transfers out of FTP.

cosmos-snapshot-public is the shared LXD custom volume: {BUILDER}:/snapshots read-write, {FTP}:{FTP_MOUNT} read-only.
Confirm LXD storage pool
lxc storage list
lxc storage show "{POOL}"
Create custom volumes
# Private receiver workspace: builder only.
lxc storage volume create "{POOL}" cosmos-snapshot-ingest

# Shared public output: builder read-write, FTP read-only.
lxc storage volume create "{POOL}" cosmos-snapshot-public
Attach builder volumes
lxc config device add "{BUILDER}" snapshot-ingest disk \
  pool="{POOL}" \
  source=cosmos-snapshot-ingest \
  path=/ingest

lxc config device add "{BUILDER}" snapshot-public-rw disk \
  pool="{POOL}" \
  source=cosmos-snapshot-public \
  path=/snapshots
Attach FTP public volume read-only
lxc config device add "{FTP}" snapshot-public-ro disk \
  pool="{POOL}" \
  source=cosmos-snapshot-public \
  path="{FTP_MOUNT}" \
  readonly=true
Shared pieces

cosmos-snapshot-public is the shared LXD custom volume.

Builder mounts it at /snapshots read-write. FTP mounts it at {FTP_MOUNT} read-only.

cosmos-snapshot-ingest is builder-only and holds partial uploads before publish.

Separate FTP subnet

The containers can use separate LXC network devices or subnets. Sharing is via LXD storage, not container networking.

Only two routes matter: source node to builder SSH, and FTP clients to FTP.

Storage safety checks
Confirm mounted paths
lxc exec "{BUILDER}" -- findmnt /ingest
lxc exec "{BUILDER}" -- findmnt /snapshots
lxc exec "{FTP}" -- findmnt "{FTP_MOUNT}"
lxc exec "{FTP}" -- sh -c 'touch "{FTP_MOUNT}/.write-test"'
Write test should fail. If it succeeds, FTP is not read-only.

3. Prepare the builder container

Install tools, create the upload user, and add server scripts.

ToolsInstall runtime deps.

Python, rsync, SSH, tar, zstd.

AccountDedicated upload user.

Writes only through wrapper/finalizer.

ScriptsWrapper and finalizer.

Authorize, validate, publish.

Install dependencies
lxc exec "{BUILDER}" -- apt-get update
lxc exec "{BUILDER}" -- apt-get install -y python3 rsync openssh-server tar zstd
Create upload user and dirs
lxc exec "{BUILDER}" -- sh -c 'getent group "{UPLOAD_USER}" >/dev/null || groupadd --system "{UPLOAD_USER}"'
lxc exec "{BUILDER}" -- sh -c 'id -u "{UPLOAD_USER}" >/dev/null 2>&1 || useradd --system --create-home --home-dir "/var/lib/{UPLOAD_USER}" --shell /bin/sh --gid "{UPLOAD_USER}" "{UPLOAD_USER}"'
lxc exec "{BUILDER}" -- install -d -o "{UPLOAD_USER}" -g "{UPLOAD_USER}" -m 0750 /ingest
lxc exec "{BUILDER}" -- install -d -o "{UPLOAD_USER}" -g "{UPLOAD_USER}" -m 0755 /snapshots
Push scripts
lxc file push scripts/cosmos-snapshot-remote "{BUILDER}/usr/local/sbin/cosmos-snapshot-remote"
lxc file push scripts/cosmos-snapshot-finalize "{BUILDER}/usr/local/sbin/cosmos-snapshot-finalize"
lxc exec "{BUILDER}" -- chmod 0755 /usr/local/sbin/cosmos-snapshot-remote /usr/local/sbin/cosmos-snapshot-finalize
Why /bin/sh

OpenSSH forced commands need a valid shell. Confinement comes from authorized_keys, not nologin.

Script behavior
  • cosmos-snapshot-remote authorizes prepare, rsync, bootstrap, status, and finalize.
  • The wrapper maps rsync/bootstrap data to /ingest/<chain>/data.
  • The finalizer refuses partial-transfer markers.
  • The finalizer keeps one completed archive per chain.

Config boundaries

ALLOW_CLIENT_ID_ARG=0 means identity comes from forced SSH. Do not ask users to pass --client-id.

SOURCE_SUBDIR=data matches the wrapper destination: /ingest/<chain>/data.

5. Force SSH through the wrapper

External writes use rsync over SSH. The key must run only the remote wrapper.

IdentityForced command sets client id.

Do not trust client-supplied ids.

ConfinementNo shell, ports, agent, X11, or TTY.

The key runs only the wrapper.

NetworkBind SSH to VPN/LAN.

The router VPN is the public entry point.

Prepare authorized_keys
lxc exec "{BUILDER}" -- install -d -o "{UPLOAD_USER}" -g "{UPLOAD_USER}" -m 0700 "/var/lib/{UPLOAD_USER}/.ssh"
lxc exec "{BUILDER}" -- touch "/var/lib/{UPLOAD_USER}/.ssh/authorized_keys"
lxc exec "{BUILDER}" -- chown "{UPLOAD_USER}:{UPLOAD_USER}" "/var/lib/{UPLOAD_USER}/.ssh/authorized_keys"
lxc exec "{BUILDER}" -- chmod 0600 "/var/lib/{UPLOAD_USER}/.ssh/authorized_keys"
Authorized key line shape
command="/usr/bin/env COSMOS_SNAPSHOT_CLIENT_ID={CLIENT_ID} /usr/local/sbin/cosmos-snapshot-remote --config /etc/cosmos-snapshot-remote.env",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA_REPLACE_WITH_CLIENT_PUBLIC_KEY {CLIENT_ID}
Expose SSH if needed
lxc config device add "{BUILDER}" snapshot-ssh proxy \
  listen=tcp:{SSH_BIND_ADDR}:{SSH_PORT} \
  connect=tcp:127.0.0.1:22
Forced-command scope

The source operator can request prepare, rsync, bootstrap, status, or finalize. No shell, port forwarding, TTY, arbitrary paths, or unlisted chains.

Bind the proxy to the VPN/LAN address. The router VPN is the outside entry point.

SSH daemon checks
Inside builder
lxc exec "{BUILDER}" -- systemctl enable --now ssh
lxc exec "{BUILDER}" -- systemctl status ssh --no-pager
lxc exec "{BUILDER}" -- ss -ltnp

If the distro uses sshd instead of ssh, adjust service name.

No ingest storage.

First two commands pass. Write test fails.

Hide finalizer staging paths from FTP

The finalizer writes temp files under /snapshots/<chain>/.tmp. FTP must not list or serve dot paths.

Read-only blocks writes, not reads.

StagingSeparate local or mounted path.

Install source deps
# Run on the source node as root/sudo.
apt-get update

Run before first dry run to confirm node home, data subdir, and staging are separate.
Staging preflight
python3 -c 'from pathlib import Path
node_home = Path("{USER_NODE_HOME}").expanduser().resolve()
data = (node_home / "{USER_DATA_SUBDIR}").resolve()
staging = Path("{USER_STAGING_PATH}").expanduser().resolve()
if not node_home.is_dir():
    raise SystemExit(f"NODE_HOME does not exist or is not a directory: {node_home}")
if not data.is_dir():
    raise SystemExit(f"DATA_SUBDIR does not exist or is not a directory under NODE_HOME: {data}")
if node_home not in data.parents:
    raise SystemExit("DATA_SUBDIR must resolve under NODE_HOME")
if data == staging or data in staging.parents or staging in data.parents:
    raise SystemExit("STAGING_PATH must be separate from source data path")'
python3 -c 'from pathlib import Path
staging = Path("{USER_STAGING_PATH}").expanduser()
staging.parent.mkdir(parents=True, exist_ok=True)
staging.parent.chmod(0o750)'
User-side values
  • NODE_HOME contains config/, data/, and keyrings, for example ~/.genesisd.
  • DATA_SUBDIR is usually data; only that subdir is inspected.
  • SERVICE_NAME is the local systemd service stopped during staging.
  • STAGING_PATH is a separate local or mounted path maintained by rsync.
  • UPLOAD_SCHEDULE is used only by the optional timer.
  • BUILDER_SSH, BUILDER_SSH_PORT, and REMOTE_COMMAND are the exposed builder details.
Source-side safety policy

The upload tool stages only public DB dirs from NODE_HOME/DATA_SUBDIR: application.db, blockstore.db, state.db, evidence.db, and tx_index.db.

It rejects validator state, keys, keyrings, WAL directories, state-sync snapshots, and arbitrary top-level paths.

CLIENT_ID stays blank; forced-command SSH identifies the user.

Optional timer
cat > /etc/systemd/system/cosmos-snapshot-upload.service <<'EOF'
[Unit]
Description=Upload Cosmos snapshot database to builder
Wants=network-online.target
After=network-online.target
ConditionPathExists=/etc/cosmos-snapshot/source-upload.env

[Service]
Type=oneshot
ExecStart=/usr/local/bin/cosmos-snapshot-upload --config /etc/cosmos-snapshot/source-upload.env
Nice=10
IOSchedulingClass=best-effort
IOSchedulingPriority=7
EOF

cat > /etc/systemd/system/cosmos-snapshot-upload.timer <<'EOF'
[Unit]
Description=Run Cosmos snapshot upload on schedule

[Timer]
OnCalendar={USER_UPLOAD_SCHEDULE}
RandomizedDelaySec=2h
Persistent=true
Unit=cosmos-snapshot-upload.service

[Install]
WantedBy=timers.target
EOF

systemctl daemon-reload
systemctl enable --now cosmos-snapshot-upload.timer
systemctl list-timers cosmos-snapshot-upload.timer
Upload flow

The helper stops service, validates NODE_HOME/DATA_SUBDIR, stages allowed DB dirs, restarts, transfers, checksum-verifies, and requests finalization.

Dry run prints planned commands. Real upload validates while the service is stopped.

Bootstrap use

Use --bootstrap once when remote ingest is empty. It streams staged DB tar into builder ingest, then checksum-verifies.

After that, use normal rsync manually or by timer.

Do not use bootstrap for routine updates; it replaces remote ingest data.

--no-finalize

Use --no-finalize only for inspection before publish. The transfer marker remains until finalization succeeds.

Upload without publishing
cosmos-snapshot-upload --config /etc/cosmos-snapshot/source-upload.env --no-finalize
User failures
  • missing required Tendermint DB directory: wrong node home, data subdir, or DB layout.
  • STAGING_PATH must be separate from source data path: choose a different staging root.
  • remote rsync verification found pending changes: upload differs from staging; retry before finalizing.
  • client is not allowed: forced-command client id and allowlist do not match.

9. Validate first snapshot

Check auth, identity, mounts, and archive integrity.

StatusWrapper identity matches.

Chain and client id must match access control.

ArtifactArchive, checksum, manifest, latest links.

All must exist before publish is complete.

FTPRead only.

FTP reads public files and fails write tests.

Wrapper status
lxc exec "{BUILDER}" -- env COSMOS_SNAPSHOT_CLIENT_ID="{CLIENT_ID}" \
  /usr/local/sbin/cosmos-snapshot-remote \
  --config /etc/cosmos-snapshot-remote.env \
  status --chain "{CHAIN}"
After first finalize
lxc exec "{BUILDER}" -- ls -la "/snapshots/{CHAIN}"
lxc exec "{BUILDER}" -- sh -c 'cd "/snapshots/{CHAIN}" && sha256sum -c latest.sha256'
lxc exec "{BUILDER}" -- tar -tf "/snapshots/{CHAIN}/latest.tar.zst" --use-compress-program=zstd >/dev/null
lxc exec "{FTP}" -- ls -la "{FTP_MOUNT}/{CHAIN}"
What success means

Status proves client id and chain allowlist. Archive checks prove validation finished before latest.* moved.

Common failures
  • missing COSMOS_SNAPSHOT_CLIENT_ID: key is not forced through the wrapper, or local test lacks env.
  • not allowed: client id and chain do not match /etc/cosmos-snapshot-access.json.
  • refusing to package while transfer markers exist: transfer failed or is active; do not publish partial data.
  • required DB directory has no recognizable DB marker: wrong path or incomplete DB.

10. Operate safely

Keep one archive, public-only FTP, explicit allowlists, and no manual source-data repair.

RetentionLet the finalizer prune.

Manual deletion is destructive.

RecoveryFailed transfers leave markers.

Retry upload; do not force publish.

AccessRotate clients in allowlist.

Keep SSH ids and JSON in sync.

1
Rotate clients through access control. Update /etc/cosmos-snapshot-access.json and matching forced-command keys.
2
Let the finalizer own retention. It prunes old archives after a new one validates and publishes.
3
Do not expose ingest. Public services get the read-only public volume and hide dot paths.
4
Do not repair source data on builder. Builder packages only what it receives after validation.
Failed upload recovery

A failed transfer leaves /ingest/{CHAIN}/.transfer-in-progress. The finalizer refuses to publish while it exists.

Confirm no rsync is active, then rerun source upload. Do not delete the marker just to publish.

Audit checklist
Periodic server checks
lxc config device show "{BUILDER}"
lxc config device show "{FTP}"
